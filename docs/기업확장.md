# 피감사회사 확장 설계안 — 제조 · 바이오 · IT

아직 구현하지 않았다. **시안 확정 후 착수한다.** 이 문서는 그때 그대로 따라가기 위한 설계다.

---

## 왜 회사를 늘리는가

다양성 때문이 아니라 **시험 범위 커버리지** 때문이다.

지금 ㈜서린정밀 하나로는 이 논점들을 영영 못 만난다.

- IT일반통제 · 자동통제 의존 · 데이터 신뢰성 (KSA 315 부록 · 330)
- 서비스조직 (KSA 402)
- 개발비 자산화 · 무형자산 손상 (KSA 540 + K-IFRS 1038 · 1036)
- 변동대가 · 수행의무 (K-IFRS 1115)
- 이익 기준이 무의미할 때의 중요성 결정 (KSA 320)

`docs/진단.md` 의 결론은 **「감사절차 수행과 결과 보고」가 배점의 60%인데 4회 내내 40% 고정**이었다.
그 영역을 더 두껍게 덮으려면 재고·조회만으로는 부족하다.

## 두 축을 섞지 않는다

| 축 | 무엇을 정하는가 | 언제 정해지는가 | 이미 있나 |
|---|---|---|---|
| **회사** | 어떤 논점을 묻는가 | 플레이어가 고른다 | ✗ 새로 만든다 |
| **시즌(시드)** | 이번에 무엇이 숨어 있는가 | 무작위 (코드 고정 가능) | ✓ 있다 (진실 8개 · 조건부 장면 · 판본) |

"부정이 존재하는 상황", "특수관계자 거래가 존재하는 상황"은 **회사가 아니라 시즌 축**이다.
이미 그렇게 돌아가고 있다 — 가공 매출채권과 순환거래는 매 시즌 존재하고, 찾아내면
「부정 혐의 대응」 장면이 열린다.

회사가 늘면 **같은 사건이 업종별로 다른 얼굴**을 갖게 된다. 이게 진짜 이득이다.

| 사건 | 제조 | 바이오 | IT |
|---|---|---|---|
| 부정 | 창고 D열을 비워 두고 재고 과대계상 | 임상 데이터 선별 공시, 실패 부문 개발비 유지 | 접근권한으로 매출 데이터 임의 수정 |
| 특수관계자 | 대표이사 배우자 법인에 가공 매출 | 대표이사 지배 벤처에 위탁연구비 과다 지급 | 대표이사 지분 SI 하청에 일감 몰아주기 |
| 계속기업 | 차입약정 위반 · 만기 집중 | **적자 지속 · 임상 실패 시 자금 고갈** (자주 열린다) | 드묾 |

### 새 장면 스펙 — 논점 수준

#### 바이오 ③ 개발비 자산화 (KSA 540 · K-IFRS 1038)

CFO: "임상 2상 진입했으면 자산화 요건은 충족된 겁니다. 감사인마다 말이 다르시네요."

| 칸 | 묻는 것 | 필수 논점 |
|---|---|---|
| ① | 자산화 개시 시점의 판단 *(판단형)* | 개발단계 진입 여부를 **6요건**으로 판단 / 기초연구 단계 지출은 비용 / "임상 2상 = 자동 자산화"는 오개념 |
| ② | 경영진 판단의 근거 검증 | 기술적 실현가능성 입증 문서 / 미래경제적효익 입증(시장·계약) / 지출의 신뢰성 있는 측정 |
| ③ | 파이프라인별 구분 | 프로젝트별 구분 집계 / 공통비 배부 기준의 합리성 |

**트랩**: 임상 단계만으로 결론 / 경영진 전문가 의견서 무비판 수용

## 아키텍처 변경

현재 코드는 회사가 하나라는 전제가 여기저기 박혀 있다. 순서대로 걷어낸다.

### 1단계 — 회사를 데이터로 (콘텐츠 변경 0)

```js
// data/company.js (신규)
window.COMPANIES = {
  seorin: {
    id: 'seorin', name: '㈜서린정밀', market: '코스닥', industry: '이차전지 장비 제조',
    firm: '세종회계법인', fy: '20×6년 12월 31일',
    revenue: '1,284억원', assets: '1,702억원', ni: '61억원',
    mat: 12, pm: 8.4, trivial: 0.6, matBasis: '세전이익의 5%',
    hook: '물건이 어디 있는지, 진짜 있는지를 본다',
    slots: { core1: 's3', core2: 's5' },   // 업종 전용 슬롯
    cast: { cfo: { name: '박정후', role: '재무담당임원' } }
  },
  // raon, nexton …
};
```

- `SEASON.create({ seed, seat, company })` → `S.company`
- `MAT` 상수 → `S.company.mat` (`decide()` · `misstatements()` · `buildMisstatements()` 3곳)
- **텍스트 템플릿** — `resolve()` 에서 `{회사}` `{업종}` `{중요성}` `{수행중요성}` 치환.
  `situation` · `exhibits` · `parts` 는 이미 `function (v, S)` 를 지원하므로 `S.company` 를 바로 읽으면 된다.
  정적 문자열(`line` · `prompt`)만 템플릿 패스를 태운다
- 장면에 `only: ['seorin']` — 기존 `sceneList()` 필터에 한 줄 추가하면 끝난다
  (조건부 장면 machinery 를 그대로 쓴다)
- `data/truth.js` → `window.TRUTH = { seorin: [...], raon: [...], nexton: [...] }`
- 타이틀 화면에 회사 선택 (시안 대기 중 — 요청서 7번)
- `tools/validate.js` → 회사 × 좌석 × 성향 × 시즌으로 확장

이 단계까지는 **서린정밀만 있어도 돌아간다.** 회귀가 없는지 먼저 확인하고 넘어간다.

### 2단계 — 바이오

`data/scenes-bio.js` — 전용 장면 2개 + 진실 5개 + 인물.

### 3단계 — IT
