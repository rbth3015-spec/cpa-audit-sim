# 피감사회사 확장 — 제조 · 바이오 · IT

설계안으로 시작해 **구현까지 끝냈다.** 앞쪽 절반(왜 늘리는가 · 두 축 · 회사 3곳 ·
장면 매트릭스 · 진실 세트)은 설계 당시 그대로 두었고, 뒤쪽 「구현 결과」에
실제로 무엇이 어떻게 들어갔는지와 설계에서 **달라진 것**을 적었다.

---

## 왜 회사를 늘리는가

다양성 때문이 아니라 **시험 범위 커버리지** 때문이다.

지금 ㈜서린정밀 하나로는 이 논점들을 영영 못 만난다.

- IT일반통제 · 자동통제 의존 · 데이터 신뢰성 (KSA 315 부록 · 330)
- 서비스조직 (KSA 402)
- 개발비 자산화 · 무형자산 손상 (KSA 540 + K-IFRS 1038 · 1036)
- 변동대가 · 수행의무 (K-IFRS 1115)
- 이익 기준이 무의미할 때의 중요성 결정 (KSA 320)

`docs/진단.md` 의 결론은 **「감사절차 수행과 결과 보고」가 배점의 60%인데 4회 내내 40% 고정**이었다.
그 영역을 더 두껍게 덮으려면 재고·조회만으로는 부족하다.

## 두 축을 섞지 않는다

| 축 | 무엇을 정하는가 | 언제 정해지는가 | 이미 있나 |
|---|---|---|---|
| **회사** | 어떤 논점을 묻는가 | 플레이어가 고른다 | ✗ 새로 만든다 |
| **시즌(시드)** | 이번에 무엇이 숨어 있는가 | 무작위 (코드 고정 가능) | ✓ 있다 (진실 8개 · 조건부 장면 · 판본) |

"부정이 존재하는 상황", "특수관계자 거래가 존재하는 상황"은 **회사가 아니라 시즌 축**이다.
이미 그렇게 돌아가고 있다 — 가공 매출채권과 순환거래는 매 시즌 존재하고, 찾아내면
「부정 혐의 대응」 장면이 열린다.

회사가 늘면 **같은 사건이 업종별로 다른 얼굴**을 갖게 된다. 이게 진짜 이득이다.

| 사건 | 제조 | 바이오 | IT |
|---|---|---|---|
| 부정 | 창고 D열을 비워 두고 재고 과대계상 | 임상 데이터 선별 공시, 실패 부문 개발비 유지 | 접근권한으로 매출 데이터 임의 수정 |
| 특수관계자 | 대표이사 배우자 법인에 가공 매출 | 대표이사 지배 벤처에 위탁연구비 과다 지급 | 대표이사 지분 SI 하청에 일감 몰아주기 |
| 계속기업 | 차입약정 위반 · 만기 집중 | **적자 지속 · 임상 실패 시 자금 고갈** (자주 열린다) | 드묾 |

## 구현 결과

설계의 1~3단계를 한 번에 넣었다. 실제 구조는 아래와 같다.

### 회사를 데이터로 (`data/company.js`)

```js
window.COMPANIES = { seorin: {...}, raon: {...}, nexton: {...} };
window.COMPANY_DEFAULT = 'seorin';
```

한 회사는 **표지 정보**(이름·시장·업종·법인·기준일·재무수치), **중요성 3종**
(`mat` · `pm` · `trivial`)과 그 근거(`matBasis`), **전반성 문턱**(`pervasive`),
**유동성 압박 확률**(`stressP`), 그리고 공통 장면이 읽어 가는 **사실관계 묶음**
(`engage` · `risk` · `confirm` · `related` · `gc` · `sub`)으로 이루어진다.

사실관계 묶음이 핵심이다. 공통 장면은 논점이 업종과 무관하므로 장면을 복제하지
않고 **숫자와 상대방만 회사에서 받아 간다.**

```js
// data/scenes1.js — 외부조회. 장면은 하나인데 회사마다 조회 대상이 다르다
situation: function (v, S) {
  return S.co.confirm.subject + ' 조회를 발송하였다. …';
}
```

### 두 가지 치환 경로

| 쓰는 곳 | 방법 |
|---|---|
| 정적 문자열 (`line` · `prompt` · `model` …) | `{회사}` `{중요성}` 같은 토큰을 `resolve()` 끝에서 일괄 치환 |
| 사실관계가 필요한 문장 (`situation` · `exhibits` · `say` · `ask`) | `function (v, S)` 로 쓰고 `S.co.*` 를 직접 읽는다 |

토큰은 `{회사} {업종} {시장} {법인} {중요성} {수행중요성} {사소한금액} {매출} {자산} {기준일}`.
**채점 라벨과 키워드는 절대 치환하지 않는다** — 라벨이 분기·진실 발견의 계약이기 때문이다.

설계에서 달라진 점: `line` · `say` · `ask` 도 함수로 쓸 수 있어야 했다.
`season.js` 에 `voice(x, v, S)` 를 두어 **함수를 먼저 펼치고 좌석을 고르도록** 했다
(문자열 · 좌석별 묶음 · 함수 세 가지를 모두 받는다).

### 장면 순서 — `ord`

장면 파일이 넷으로 나뉘면서 `window.SCENES` 의 배열 순서가 곧 파일 로드 순서가 됐다.
그대로 두면 업종 전용 장면이 의견형성 뒤에 붙는다. 그래서 **시간축은 `ord` 가 단독으로 정한다.**

```js
// js/season.js
function sceneList(S) {
  return global.SCENES.filter(function (sc) {
    if (S.played[sc.id]) return true;
    if (sc.only && sc.only.indexOf(S.company) < 0) return false;   // 업종 전용
    return !sc.when || sc.when(S);                                  // 조건부
  }).sort(function (a, b) { return a.ord - b.ord; });
}
```

`ord` 는 s1:10 · s2:20 · **③슬롯:30** · s4:40 · **⑤슬롯:50** · s6:60 · s6f:65 ·
s7:70 · s7g:75 · s8:80 · s9:90 · s10:100. 전용 장면은 슬롯 번호만 맞추면 제자리에 꽂힌다.

### 회사 선택 화면

타이틀 화면에 회사 카드 3장. 고르면 **표지·시즌 길이·중요성 근거가 즉시 바뀐다.**
자리 선택과 같은 규칙(6px 선이 선택을 말한다)을 쓰되, 카드에 업종 한 줄과
중요성 기준을 같이 적었다 — 중요성 벤치마크의 선택 자체가 학습 포인트라서다.

> 설계의 열린 질문 1 「고르게 할 것인가, 배정할 것인가」 는 **고르게 하는 쪽**으로 정했다.

> 반복 연습**하는 쓸모가 크다. 편식은 기록 표에 회사 열을 두어 스스로 보이게 했다.
