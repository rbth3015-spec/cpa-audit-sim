# 디자인 협업 기록 — Claude Design ↔ 코드

디자인이 어떻게 들어와서 어떻게 코드가 되는지를 남긴다.
다음 라운드에서 같은 것을 다시 묻지 않고, 같은 실수를 반복하지 않기 위한 기록이다.

역할은 이렇게 나눈다.

| | 하는 일 | 산출물 |
|---|---|---|
| **Claude Design** | 화면을 그린다. 토큰 · 치수 · 연출 타이밍을 확정한다 | `.dc.html` 아트보드 · 핸드오프 README |
| **여기(코드)** | 그 뼈대를 실제 게임에 입힌다. 상태 · 데이터 · 접근성을 붙인다 | `index.html` · `js/game.js` · `js/art.js` |

**단일 진실은 코드다.** 시안이 확정값을 주지만, 일단 옮겨진 뒤로는 `index.html` 의
`:root` 토큰과 `as-*` 클래스가 기준이다. 시안과 코드가 어긋나면 코드를 고치는 게 아니라
어느 쪽이 맞는지 먼저 정한다.

## 라운드 1 — 「감사 시즌 2026」 Modernist 시안 (2026-09-14, `bfa142f`)

### 받은 것

- `감사 시즌 2026.dc.html` — 5개 화면(타이틀 · 플레이 · 판정 · 엔딩 · 연출) 전체
- 핸드오프 `README.md` — 토큰 표 · 치수 · 애니메이션 정의 · 화면별 구성
- `support.js` · `image-slot.js` — 시안 전용 런타임

### 가져온 것 (뼈대)

- 토큰 `--as-*` 전체, 라이트/다크, `data-theme` 수동 오버라이드
- 규칙: radius 0 / 구조선 2px · 내부선 1px / flush left / 빨강은 주 액션 · 위험에만 / `tabular-nums`
- 화면 구성과 컴포넌트 — HUD · 무대 · 대사 박스 · 브리핑 · 자료 · 문항 · 답안 · 타이머 링 ·
  판정 헤드 · 등급 도장 · 논점 행 · 엔딩 히어로 · 감리 도장 · 와이프 · 토스트
- 연출 9종과 타이밍(`as-rise` `.4~.5s` stagger 60ms, 와이프 1.6s, 토스트 7s …)

### 버린 것 (의도적으로)

- **시안의 게임 규칙** — 장면 1개 = 문항 1개, 게이지 3종, 고정 10장면.
  이 게임은 한 장면이 짧은 칸 2~3개이고 게이지가 4종이며 시즌 길이가 10~12로 변한다.
  시안은 **디자인 레퍼런스**이지 기획서가 아니다
- **시안 런타임** — `support.js` · `<x-dc>` · `{{ }}` 홀 · `<sc-if>` 는 재현 대상이 아니다.
  조건부 렌더링과 상태는 이 코드베이스 방식(바닐라 JS + `season.js`)으로 다시 썼다
- **`image-slot.js`** — 프로토타입 전용 플레이스홀더. 일반 `<img>` + `object-fit:cover` + CSS 필터로 대체

### 시안에 없어서 임의로 만든 것

시안은 5개 화면만 있었고, 이 게임에는 그 밖에도 화면이 있다. 임시로 만들었고 **라운드 2에서 제대로 받는다.**

조서 서랍 · 좌석 선택 · 개념 카드/오답노트 · 모바일 레이아웃 · 진행도 표시

### 옮기면서 드러난 문제 (디자인 쪽도 알아 둘 것)

| 문제 | 원인 | 해결 |
|---|---|---|
| 좁은 화면에서 무대가 가로로 넘쳤다 | `aspect-ratio: 16/7` + `min-height: 300px` 만 주면 브라우저가 **높이에서 폭을 역산**한다 (300 × 16/7 = 686px) | `aspect-ratio` 를 쓰는 박스에는 `max-width: 100%` 를 반드시 같이 |
| 엔딩 감리 도장이 아래로 쏠렸다 | 세로 가운데 맞춤(`translateY(-50%)`)과 찍히는 연출(`scale`·`rotate`)을 **한 요소의 `transform`** 에 줬더니 애니메이션이 정렬을 덮어썼다 | 정렬은 바깥 요소, 연출은 안쪽 요소 |
| 시안에 `prefers-reduced-motion` 대응이 없었다 | 핸드오프 README 에 "미구현 — 구현 시 반드시 추가" 로 명시되어 있었다 | 전 연출에 대응 추가. **다음 시안부터는 처음부터 포함** |
| 판정 기호 ○ △ ✕ ⚠ 가 모양만으로 의미를 전달 | — | 전부 `aria-label` 병기. 게이지는 `role="progressbar"` |

### 확인 방법 (매 라운드 동일)

Chromium(Playwright)으로 시즌을 끝까지 돌린다. 통과 기준:

- 콘솔 오류 0 · 엔딩 도달
- 라이트 / 다크 둘 다
- 1280px / 400px 둘 다, **가로 스크롤 없음**
- `prefers-reduced-motion: reduce` 에서 연출이 사라지고 최종 상태가 즉시 보이는가
- `node tools/validate.js` 통과 (디자인 변경이 로직을 건드리지 않았는가)

## 라운드 2 — 진행 중 (요청서: `docs/디자인요청.md`)

### 이번 라운드의 전제

**사진은 뺐다.** 13장을 구하는 데 시간이 오래 걸려서, 사진 없이도 완성된 화면을 먼저 만든다.
그래서 이번 요청의 핵심 하나가 늘었다 — **"사진이 없는 상태"를 임시가 아니라 정식 상태로 디자인할 것.**

지금은 `js/art.js` 가 무채색 인라인 SVG 로 자리를 대신하고 있다. 이게 최종인지,
아니면 기하학적·타이포그래피적 처리로 갈 것인지 디자인 쪽에서 정해 줘야 한다.

### 요청한 것

화면 7종 — 조서 서랍 · 좌석 선택 · 개념 카드/오답노트 · 진행도 · 모바일 플레이 ·
메신저 자료 · **회사 선택**(다음 단계인 피감사회사 3곳을 위해 미리)

### 돌려받을 때의 계약

- `.dc.html` 아트보드 하나에 모아서
- 지금 코드의 클래스명(`as-dossier` `as-seat` `as-card` `as-ask` `as-prog` …)을 그대로 쓰면 바로 옮긴다
- **상태 변형을 같이** 줘야 한다. 비어 있을 때 · 가득 찼을 때 · 위험할 때.
  라운드 1에서 상태 변형 카드(분량 초과 · 타이머 위기 · 신뢰 급락)가 같이 와서 크게 도움이 됐다
