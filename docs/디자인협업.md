# 디자인 협업 기록 — Claude Design ↔ 코드

디자인이 어떻게 들어와서 어떻게 코드가 되는지를 남긴다.
다음 라운드에서 같은 것을 다시 묻지 않고, 같은 실수를 반복하지 않기 위한 기록이다.

역할은 이렇게 나눈다.

| | 하는 일 | 산출물 |
|---|---|---|
| **Claude Design** | 화면을 그린다. 토큰 · 치수 · 연출 타이밍을 확정한다 | `.dc.html` 아트보드 · 핸드오프 README |
| **여기(코드)** | 그 뼈대를 실제 게임에 입힌다. 상태 · 데이터 · 접근성을 붙인다 | `index.html` · `js/game.js` · `js/art.js` |

**단일 진실은 코드다.** 시안이 확정값을 주지만, 일단 옮겨진 뒤로는 `index.html` 의
`:root` 토큰과 `as-*` 클래스가 기준이다. 시안과 코드가 어긋나면 코드를 고치는 게 아니라
어느 쪽이 맞는지 먼저 정한다.

## 라운드 1 — 「감사 시즌 2026」 Modernist 시안 (2026-09-14, `bfa142f`)

### 받은 것

- `감사 시즌 2026.dc.html` — 5개 화면(타이틀 · 플레이 · 판정 · 엔딩 · 연출) 전체
- 핸드오프 `README.md` — 토큰 표 · 치수 · 애니메이션 정의 · 화면별 구성
- `support.js` · `image-slot.js` — 시안 전용 런타임

### 가져온 것 (뼈대)

- 토큰 `--as-*` 전체, 라이트/다크, `data-theme` 수동 오버라이드
- 규칙: radius 0 / 구조선 2px · 내부선 1px / flush left / 빨강은 주 액션 · 위험에만 / `tabular-nums`
- 화면 구성과 컴포넌트 — HUD · 무대 · 대사 박스 · 브리핑 · 자료 · 문항 · 답안 · 타이머 링 ·
  판정 헤드 · 등급 도장 · 논점 행 · 엔딩 히어로 · 감리 도장 · 와이프 · 토스트
- 연출 9종과 타이밍(`as-rise` `.4~.5s` stagger 60ms, 와이프 1.6s, 토스트 7s …)

### 버린 것 (의도적으로)

- **시안의 게임 규칙** — 장면 1개 = 문항 1개, 게이지 3종, 고정 10장면.
  이 게임은 한 장면이 짧은 칸 2~3개이고 게이지가 4종이며 시즌 길이가 10~12로 변한다.
  시안은 **디자인 레퍼런스**이지 기획서가 아니다
- **시안 런타임** — `support.js` · `<x-dc>` · `{{ }}` 홀 · `<sc-if>` 는 재현 대상이 아니다.
  조건부 렌더링과 상태는 이 코드베이스 방식(바닐라 JS + `season.js`)으로 다시 썼다
- **`image-slot.js`** — 프로토타입 전용 플레이스홀더. 일반 `<img>` + `object-fit:cover` + CSS 필터로 대체

### 시안에 없어서 임의로 만든 것

시안은 5개 화면만 있었고, 이 게임에는 그 밖에도 화면이 있다. 임시로 만들었고 **라운드 2에서 제대로 받는다.**

조서 서랍 · 좌석 선택 · 개념 카드/오답노트 · 모바일 레이아웃 · 진행도 표시

### 옮기면서 드러난 문제 (디자인 쪽도 알아 둘 것)

| 문제 | 원인 | 해결 |
|---|---|---|
| 좁은 화면에서 무대가 가로로 넘쳤다 | `aspect-ratio: 16/7` + `min-height: 300px` 만 주면 브라우저가 **높이에서 폭을 역산**한다 (300 × 16/7 = 686px) | `aspect-ratio` 를 쓰는 박스에는 `max-width: 100%` 를 반드시 같이 |
| 엔딩 감리 도장이 아래로 쏠렸다 | 세로 가운데 맞춤(`translateY(-50%)`)과 찍히는 연출(`scale`·`rotate`)을 **한 요소의 `transform`** 에 줬더니 애니메이션이 정렬을 덮어썼다 | 정렬은 바깥 요소, 연출은 안쪽 요소 |
| 시안에 `prefers-reduced-motion` 대응이 없었다 | 핸드오프 README 에 "미구현 — 구현 시 반드시 추가" 로 명시되어 있었다 | 전 연출에 대응 추가. **다음 시안부터는 처음부터 포함** |
| 판정 기호 ○ △ ✕ ⚠ 가 모양만으로 의미를 전달 | — | 전부 `aria-label` 병기. 게이지는 `role="progressbar"` |

### 확인 방법 (매 라운드 동일)

Chromium(Playwright)으로 시즌을 끝까지 돌린다. 통과 기준:

- 콘솔 오류 0 · 엔딩 도달
- 라이트 / 다크 둘 다
- 1280px / 400px 둘 다, **가로 스크롤 없음**
- `prefers-reduced-motion: reduce` 에서 연출이 사라지고 최종 상태가 즉시 보이는가
- `node tools/validate.js` 통과 (디자인 변경이 로직을 건드리지 않았는가)

## 라운드 2 — 받았다 (v2 · v3)

### 온 것

| 파일 | 내용 |
|---|---|
| `감사 시즌 2026 v2.dc.html` | 정적 조서 한 장. 조서 레이아웃·타이포 규칙의 원형 |
| `감사 시즌 2026 v3.dc.html` | 플레이 루프 완성본. 증거 채택 → 판단 3지선다 → 서술 → 채점 → 장면 전환 → 중간 평정 |
| `README.md` · `CLAUDE_CODE_PROMPT.md` | 핸드오프 명세 (토큰·컴포넌트·상태·애니메이션) |

요청서에 없던 것이 왔다. **게임 루프 전체를 다시 설계해서** 보냈다.
증거 셀을 눌러 채택하고, 판단을 3지선다로 고르고, 80자 이상 서술하면
`선택지 기본점 + 증거수×4 + 글자수` 로 채점하는 구조다.

### 판단 — 뼈대는 코드 쪽을 유지한다

라운드 1의 계약("기능은 참고하지 않는다, 큰 틀과 뼈대만 가져온다")을 이번에도 지켰다.
시안의 게임 규칙은 **가져오지 않았다.**

| 가져오지 않은 것 | 이유 |
|---|---|
| 판단 3지선다 (`pick` 단계) | 이 게임은 **답안을 쓰는 것**이 유일한 대응이다. 선택지를 주면 출력 연습이 사라진다 |
| 증거 클릭 채택 | 같은 이유. 증거는 눌러서 얻는 게 아니라 **절차를 서술해서** 얻는다 |
| 「기본점 + 증거수×4 + 200자면 +4」 채점 | 이미 라벨 단위 루브릭 채점기(`js/engine.js`)가 있다. 부분점수·부정문 무효화·판단 추출·오개념 감점까지 한다 |
| 46px 색인 레일 단일 시트 | HUD 진행도 칩이 같은 일을 하고 있고, 400px 대응을 다시 해야 한다 |

### 가져온 것 — 조서의 질감

시안이 코드보다 확실히 나았던 지점은 **게임 규칙이 아니라 종이의 질감**이었다.
그것만 골라 왔다.

| 가져옴 | 어떻게 |
|---|---|
| **국문 명조 내러티브** | `--as-serif` 를 세우고 대사·상황·문항·답안·모범답안·검토의견을 명조로. 라벨·숫자는 그대로 sans/mono. 구글 폰트는 부르지 않는다 — `file://` 에서 돌아야 하므로 시스템 명조(바탕 · AppleMyungjo · 나눔명조)로만 내려간다 |
| **답안 괘선** | `repeating-linear-gradient` 로 32px 괘선. 줄 간격과 괘선 주기가 **같아야** 글자가 줄 위에 앉는다 |
| **회계 관행** | 합계 행 아래 `3px double` · 음수는 괄호 · 마지막 열은 감사 틱마크(`✓` 먹, 「미실사」 붉은 글자). 표 데이터는 그대로 두고 `docCell()` 이 관행을 입힌다 |
| **조서 머리** | HUD 가 말하지 않는 것만 — 누가 쓰고(작성) 누가 검토하고(검토) 이 종이의 색인번호가 무엇인지 |
| **검토 의견 = 붉은 펜** | 채점 결과의 인물 반응을 `--as-red-2` 명조로, `as-pen` clip-path 로 좌→우 필기 |
| **시스템 화면 자료 (`type: 'screen'`)** | 가장 값어치 있는 한 가지 |

### 「사진이 없는 상태」에 대한 답

요청서 0번이 물은 것 — *"사진이 없는 상태를 임시가 아니라 정식 상태로 디자인해 달라"* —
에 시안은 이렇게 답했다. **사진을 아예 쓰지 않는다. 감사인이 실제로 들여다보는
시스템 화면을 타이포와 격자로 세운다.**

이건 맞는 답이다. 창고 사진보다 **랙 점유 현황 화면에서 D열만 비어 있는 것**이
감사 장면으로서 훨씬 많은 말을 한다. `type: 'screen'` 자료로 가져왔다.

- 셀 톤 세 가지가 전부다 — `fill` 있다 / `dim` 흐리다 / `empty` **비었다**
- `empty` 만 크림색 점선이다. 이 장면에서 눈이 가야 하는 자리
- 클릭은 없다. **읽는 자료**다
- 좁은 화면에서도 열을 접지 않는다 — 격자의 자리 자체가 정보다(D열이 어디인지)

지금 두 곳에 들어가 있다. 재고실사의 **WMS 랙 점유 현황**(D열 전량 공란),
IT일반통제의 **IAM 권한 대장**(개발팀 4개 계정의 승인자 칸이 비어 있음).

무대 아트(`js/art.js`)는 그대로 둔다. 무대는 분위기를 맡고, 자료는 데이터를 맡는다.

## 여기서부터 Claude Code

디자인 왕복은 라운드 2로 닫는다. 앞으로 화면은 **코드 쪽에서 직접 고친다.**
`docs/디자인요청.md` 는 더 나가지 않는 요청서로 남겨 둔다 — 무엇을 물었고
무엇을 돌려받았는지의 기록이다.

라운드 1·2 를 거치며 남은 것은 결국 **규칙 몇 줄**이고, 그건 이제 `index.html` 의
`:root` 토큰과 `as-*` 클래스 안에 있다. 새 화면은 그 규칙으로 짠다.

- radius 0 · 구조선 2px / 내부선 1px · flush left
- 빨강은 주 액션 · 위험 · 강조 한 단어에만. **작은 붉은 글자는 `--as-red-2`**
- 서사는 명조, 라벨·숫자는 sans/mono. 숫자는 예외 없이 `tabular-nums`
- 사진 없음. 데이터는 격자와 타이포로, 분위기는 무채색 SVG 로
- `prefers-reduced-motion` 이면 연출을 지우고 최종 상태를 즉시

### 매 변경마다 확인하는 것 (그대로 유지)

- 콘솔 오류 0 · 엔딩 도달 — **세 회사 각각**
- 라이트 / 다크 둘 다
- 1280px / 400px 둘 다, 가로 스크롤 없음
- `prefers-reduced-motion: reduce` 에서 연출이 사라지고 최종 상태가 즉시 보이는가
- `node tools/validate.js` 통과 (디자인 변경이 로직을 건드리지 않았는가)
