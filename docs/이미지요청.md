# 원판 요청서 — 생성 모델로 만들 이미지 14장

사용자가 나노바나나(Gemini 이미지 모델)로 **원판(plate)** 을 만들어 보내고,
코드 쪽에서 규격 맞추기·배선·검증을 한다. 역할이 갈리는 지점을 먼저 적는다.

## 왜 나눠서 하나 — 도구 상황

Claude Code 쪽에는 **생성 모델이 없다.** 이미지 생성 도구가 툴셋에 없고 외부 API 키도 없다.
게다가 이 컨테이너에는 래스터 라이브러리가 하나도 없다 — PIL · cairosvg · ImageMagick ·
sharp · node-canvas 전부.

있는 것은 **Chromium 하나**뿐인데, 그걸로 되는 일이 셋이다.

| 되는 것 | 어떻게 | 어디에 |
|---|---|---|
| HTML/CSS/SVG → 임의 크기 PNG | Playwright 스크린샷 | `tools/shots.js` |
| 크롭 · 리사이즈 · 무채색 · 재인코딩 | 페이지 안 `<canvas>` → base64 | `tools/plates.js` |
| 절차적 생성 | 시드로 매번 다른 스카이라인 | `js/art.js` |

즉 **결정론적 생성은 되고 생성 모델은 안 된다.** 그래서 이렇게 나눈다.

```
사용자   나노바나나로 원판만 만든다. 깨끗한 사진 한 장
코드     규격서 작성 → node tools/plates.js 로 후처리 → 배선 → 검증
```

후처리는 이미 돌아간다. `node tools/plates.js <폴더>` 하면 파일 이름만 보고
규격을 골라 잘라 준다 (`face-*` 는 512×512, `title*` 은 1000×1500, `review*` 는
1800×686, 나머지는 무대 1600×700).

---

## 원판에 절대 넣지 말 것

이게 제일 중요하다. **화면에 올라가는 것은 전부 HTML 이 그린다.**
사진 안에 같은 것이 또 있으면 두 번 겹친다.

| 넣지 않는다 | 이유 |
|---|---|
| 글자 · 숫자 · 로고 · 간판 | 태그 · 캡션 · 기준일 도장이 전부 HTML 로 위에 올라간다 |
| **빨강** | `--as-red` 는 주 액션과 마킹 전용이다. 사진에 빨강이 있으면 그 규칙이 깨진다 |
| 워터마크 · 프레임 · 비네팅 | 어두운 그라디언트를 CSS 가 따로 건다 |
| 웃는 얼굴 · 악수 · 유리 빌딩 클리셰 | 스톡 티가 난다. 이 게임은 야근하는 회계법인이다 |

그리고 **무채색으로 뽑아 달라.** 코드에서 `grayscale(1) contrast(1.1~1.16)` 가
한 번 더 걸리는데, 원판부터 무채색이어야 여러 장 사이 톤이 안 튄다.
컬러로 나와도 `plates.js` 가 무채색으로 구워 주긴 한다.

**노출은 중간~밝게.** 위에 어두운 그라디언트가 깔리므로 원판이 어두우면 뭉갠다.
**가장자리에 중요한 것을 두지 않는다** — 비율이 안 맞으면 잘라낸다.

## 우선순위

아트 대지(`docs/shots/art.png`)를 보면 어디가 약한지 바로 보인다.

1. **초상 4장** ← 여기가 제일 급하다. 지금은 원 하나 + 사각형 하나라 네 사람이 구별되지 않는다
2. **무대 8장** — 지금 SVG 도 그럭저럭 읽히지만 사진이 들어오면 확실히 낫다
3. **엔딩 히어로 1장 · 타이틀 1장** — 마지막

나노바나나는 **한 장을 참조 이미지로 물려 다음 장을 뽑으면 인물·조명이 유지된다.**
초상 4장은 그렇게 뽑는 게 좋다 — 같은 렌즈, 같은 조명, 같은 사무실에서 찍은 것처럼.

## 1. 초상 4장 — 1:1, 1024×1024 이상

얼굴을 **가로 정중앙**, 위에서 **35~45% 지점**에. 웃지 않는다. 배경은 단색에 가깝게
(사무실 벽 · 블라인드 정도). 상반신, 어깨까지. 정면 또는 살짝 사선.

> 실존 인물을 닮게 하지 말 것. 가상의 인물이다.

### 공통 프롬프트 머리 (매번 앞에 붙인다)

```
Monochrome black-and-white editorial portrait of a Korean office worker,
waist-up, shoulders visible, plain office wall background, soft diffused
overhead light, neutral expression, not smiling, looking slightly off-camera.
Documentary photography, 50mm lens, medium contrast, mid-to-bright exposure.
No text, no logos, no name tags, no red, no color. Square 1:1 framing with the
face centered horizontally and positioned about 40% from the top.
```

### 인물별 꼬리

| 파일명 | 인물 | 붙일 문장 |
|---|---|---|
| `face-partner.jpg` | 정한별 · 업무수행이사 | `A man in his early 50s, grey hair, dark suit without tie, tired but composed — the person who signs the conclusion.` |
| `face-manager.jpg` | 유가온 · 시니어 | `A woman in her mid-30s, hair tied back, plain shirt with sleeves rolled up, alert and busy — the person who runs the fieldwork.` |

## 2. 무대 8장 — 16:7, 1600×700 이상

**피사체는 상단 65% 안에.** 하단 30% 는 대사 박스가 덮는다 (모바일에서 최대 55%).
사람이 있어도 되고 없어도 된다. 있으면 뒷모습·실루엣 쪽이 좋다.

### 공통 프롬프트 머리

```
Monochrome black-and-white documentary photograph, Korean corporate interior,
wide 16:7 cinematic framing, subject in the upper two-thirds of the frame,
empty floor space in the lower third, fluorescent or mixed office lighting,
medium contrast, mid-to-bright exposure, no people facing the camera.
No text, no signage, no logos, no numbers, no red, no color.
```

## 보내주면 내가 하는 것

1. `tools/plates.js` 로 규격 맞추기 — 크롭 · 리사이즈 · 무채색 · JPEG 재인코딩
2. `assets/art/` 에 넣고 `js/art.js` 를 바꾼다 — `.as-art` 안의 `<svg>` 를 `<img>` 로.
   **SVG 는 지우지 않는다.** 사진이 없는 장면은 그대로 SVG 를 쓰고, 파일이 있으면 사진을 쓴다
3. 검증 — 3회사 × (1280 / 400px) × (라이트 / 다크), 콘솔 오류 0 · 가로 스크롤 0
4. 올라가는 마킹·태그·도장이 사진 위에서도 읽히는지 눈으로 확인

파일 이름만 위 표대로 맞춰서 주면 된다. 비율이 조금 달라도 `plates.js` 가 잘라낸다.

## 자료(`type: 'screen'`)는 사진을 안 쓴다

헷갈리기 쉬운 지점이라 적어 둔다. 라운드 2 시안의 결론대로,
**감사인이 들여다보는 화면**(WMS 랙 점유 현황 · IAM 권한 대장)은 사진이 아니라
타이포와 격자로 세운다. 거기엔 사진이 들어갈 자리가 없다.

```
무대 · 초상   분위기   ← 사진이 들어갈 자리
자료          데이터   ← 타이포와 격자. 사진 안 씀
```
