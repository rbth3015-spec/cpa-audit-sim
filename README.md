# 감사 시즌 2026

CPA 2차 회계감사 **실전 시뮬레이션 게임**. 설치 없이 브라우저에서 돌아간다.

감사 시즌 하나를 수임부터 감사의견까지 끌고 간다. 회사에는 **무언가가 숨겨져 있고**, 절차를 제대로 밟은 만큼만 드러난다.
놓친 것은 1년 뒤 감리에서 돌아온다. 장면과 장면 사이에는 사람들이 메시지를 보낸다.

감사 대상은 홈에서 고른다.

세 가지를 목표로 만든다.
1. **학습** — 기출 문체 · 기준서 용어 · 즉시 채점 · 모범답안 대조 · 오답 노트 · 개념 카드
2. **게임** — 단서 찾기 · 판단 버튼 · 미니게임 · 등급 도장 · 연속 보너스 · 숨은 진실 · 36가지 엔딩
3. **쓰기 편한 화면** — 한 화면에 할 일 하나, 같은 정보는 한 번만, 문구는 라벨 · 대사 한 줄

## 실행

```bash
node tools/serve.mjs
```
`http://localhost:8765` — `python -m http.server 8765` 로 띄우거나 `index.html` 을 바로 열어도 된다(데이터를 `.js` 로 두어 `file://` 에서도 돈다). AI 연동 채점의 「이 PC」 길은 `tools/serve.mjs` 로 띄웠을 때만 있다.
웹폰트(Archivo · Gowun Batang · IBM Plex Mono · Pretendard)는 인터넷이 없으면 시스템 글꼴로 대체된다.
데스크톱 전용으로 설계했다 (1280px 이상 권장).

디자인 규칙은 인계 디자인(design_handoff_audit_season_2026)을 따른다. 조서 한 장 콘셉트, 모서리 0, 서사는 명조 · 라벨과 수치는 고딕/고정폭, 붉은색은 큰 글자 · 펜 주석 · 제출 버튼, 합계 행 이중선, `tabular-nums`, 다크 모드, `prefers-reduced-motion` 에서 애니메이션 정지.

### 문구 원칙
- UI · 안내는 라벨과 명사형 (「장면 01 / 10」 「편철 완료」 「개념 카드 +2」). 규칙 설명 문단을 두지 않는다
- 도움말은 형식마다 처음 한 번만 한 줄로 뜬다 (TIP)
- 인물 대사는 구어체 한 줄, 문제 문장을 되풀이하지 않는다
- 물음은 기출 문체 (~서술하시오 · ~고르시오 · ~채우시오 · ~분류하시오)
- 개념 카드와 해설은 수험서식 명사형 요약
- 감리 결과 · 조서 문구는 개조식 · 문어체

## 문항 형식

한 장면은 칸 3개(경로 장면은 2개)이고, 칸마다 형식이 다르다. 형식이 달라도 채점 결과는 같은 모양(must · trap)이라 분기 · 진실 발견 · 개념 카드 로직은 형식을 모른다.

| 형식 | 조작 | 채점 |
|---|---|---|
| `write` 서술 | 답안을 통으로 쓴다. `verdict` 가 있으면 판단 문장까지 써야 한다 | 키워드 엔진(정규화 · 동의어 · 오타 허용 · 부정문 무효 · 근접 조건 · 나열 상한 · 분량 감점) |
| `judge` 판단 | A/B 로 판단을 고르고 근거만 쓴다 | 판단이 틀리면 근거 0점 |
| `choice` 객관식 | 하나 고르기 / 모두 고르기. 보기는 헷갈리게 — 오답마다 왜 틀렸는지 한 줄 | 모두 고르기에서 오답은 감점, 오답 두 개 이상이면 명중 불인정 |
| `cloze` 빈칸 | 기준서 취지 문장의 핵심어 빈칸. 초성 힌트 가능 | 동의어 · 오타(자모 편집거리) 허용, 힌트 쓴 빈칸은 절반 |
| `sort` 분류 | 항목마다 분류를 고른다 (답안 양식 표처럼) | 항목별 채점, 특정 오분류는 감점 · 회사 태도에 연결 가능 |
| `mini` 미니게임 | 열 가지 — 아래 표 | 게임별 채점 규칙 (js/minis.js) |

### 미니게임
| 게임 | 쓰이는 곳 | 하는 일 | 배우는 것 |
|---|---|---|---|
| `count` 재고 실사 | 도원 장면 3 | 랙 20칸과 회사 실사표를 양방향으로 대조, 표본 8개를 세고 틱마크(일치 · 수량 차이 · 현품 없음 · 실사표 누락 · 상태 이상) | 실사표→현품 = 실재성, 현품→실사표 = 완전성, 파손 = 평가, 타사 소유 = 제외 |
| `jet` 분개 테스트 | 도원 장면 2 · 신진 장면 4 | 전표 24건에 추출 조건 9개를 조합해 위험 분개 5건을 10건 이하로 추출 | 결산 수정분개 · 마감 후 입력 · 경영진 입력 · 드문 계정 조합 · 기말 전후 매출 |
| `cutoff` 기간귀속 | 돌발 업무 c28 | 기말 전후 출고 8건을 타임라인에서 보고 귀속 오류를 표시 | 인도조건별 통제 이전 시점 (선적지 · 도착지 · 검수) |
| `confirm` 외부조회 | 돌발 업무 c29 | 조회 대상을 고르고 주소를 독립적으로 확인해 직접 발송, 회신 차이마다 조치 | 조회 과정의 통제 · 무회신과 불일치의 대체적 절차 |
| `unrec` 부외부채 탐색 | 돌발 업무 c30 | 기말 후 지급 10건을 열어 12월에 귀속될 부채를 표시 | 미기록 부채 — 기말 후 지급에서 출발하는 완전성 절차 |
| `sample` 표본 평가 | 돌발 업무 c31 | 표본 차이를 왜곡표시인지 가르고 투영 방법을 골라 허용왜곡표시와 비교 | 왜곡표시의 투영 · 이례적 항목 · 표본 결과의 평가 |
| `ic` 내부거래 대사 | 삼한 장면 4 | 회사 간 채권 · 채무 차이를 운송 중 · 환율 · 설명 안 됨으로 가르고 미실현이익 제거 기준을 고른다 | 연결 내부거래 대사 · 근거 없는 차이 · 미실현이익 |
| `attr` 통제 표본 | 대풍 장면 3 | 승인 25건을 서명 견본과 대조해 이탈 · 고의 의심을 표시하고 통제 의존 여부를 판정 | 통제 이탈 · 허용이탈률 · 의존할 수 없으면 실증절차 확대 |
| `ret` 반품 데이터 | 대풍 장면 4 | 반품 44건에 조건을 조합해 위험 반품을 20건 이하로 추출 | 부정 징후 조건 설계 · 추출 범위 |
| `site` 현장 공정 대조 | 청림 장면 3 | 공종별 현장 기록을 열어 보고된 공정률과 대조하고 공정률을 다시 추정 | 진행률 검증 · 총예정원가 재추정 |

판은 시즌 코드로 섞인다. 같은 코드면 같은 판이다.
처음 만나는 미니게임 앞에는 **방법 창**이 한 번 뜬다(보는 동안 시계는 선다). 조작만 보여 주고 답은 적지 않는다. 막대의 [방법]으로 다시 본다 — 내용은 `js/minis.js` 의 `howto(M)`.

### 갈림길과 경로 장면 (여섯 회사)
회사마다 갈림길 두 곳 × 두 갈래 = 네 경로. 어느 길로 가도 다음 장면에서 다시 만나고, 잘하면 같은 결말(지적 없음)에 닿는다.
막힌 길은 앞에서 한 선택(사람의 믿음 · 회사 태도 · 남은 시간)이 정한다. 막혀도 다른 갈래로 돌아가 끝까지 갈 수 있고, 시간이 더 들 뿐이다.

| 회사 | 갈림길 | 두 갈래 | 막히면 |
|---|---|---|---|
| 도원정밀 | 회계추정치 뒤 | 분개 전수 분석 / 제보자 면담 | 이수아의 믿음이 없으면 헛걸음 뒤 서버실로 |
| | 특수관계자 뒤 | 감사위원회 보고 / 경영진 면담 | 대표이사를 먼저 만났으면 감사위원장 연락에 바로 가야 지지 |
| 신진바이오 | 개발비 자산화 뒤 | 상대방 조회 / 연구 기록 점검 | 회사가 비협조적이면 조회가 막혀 연구 기록으로 |
| | 전환상환우선주 뒤 | 임상 데이터룸 / 증자 확약 점검 | 오예린의 믿음이 없으면 데이터룸이 닫혀 주관사로 |
| 동인정보기술 | IT 일반통제 뒤 | 개선 통제 테스트 / 전수 재계산 | 서태오를 밀어냈으면 권한 회수가 미뤄져 전수 재계산으로 |
| | 서비스조직 뒤 | 진우 현장 실사 / 발주처 조회 | 문경호를 자극했으면 진우시스템이 문을 닫아 발주처로 |
| 삼한그룹 | 부문감사인 뒤 | 하노이 직접 관여 / 다른 감사인 투입 | CFO 에게 「현지 일」을 맡겼으면 방문이 미뤄져 다른 감사인으로 |
| | 영업권 손상 뒤 | 자카르타 현장 / 감사위원회 보고 | 감사시간이 빠듯하면 출장이 취소돼 감사위원회로 |
| 대풍마켓 | 반품 데이터 뒤 | 매장 야간 현장 / 전 매장 데이터 확장 | 민효진의 제보를 흘려들었으면 셔터가 닫혀 데이터로 |
| | 미비점 평가 뒤 | 보완통제 검증 / 변경 영향 범위 | 계획 때 보고서만 받았으면 검토 증빙이 없어 영향 범위로 |
| 청림건설 | 총예정원가 뒤 | 제보 파일 검증 / 외부 단가 추정 | 나은비의 제보를 거절했으면 파일을 못 받아 외부 단가로 |
| | 붕괴 사고 뒤 | 공사 기록 추적 / 조사 결과 대기 | 장만석이 등을 돌렸으면 청주가 연결되지 않아 위원회로 |

- 놓친 사실을 되찾는 길(`TRUTH.detect.or`) — 앞 장면에서 놓친 숨은 사실도 경로 장면에서 짚으면 되살아난다. 길마다 되찾는 사실이 다르다(예: 동인정보기술의 발주처 조회는 하도급비 과다 지급과 SI 진행률 과대를 함께 잡는다).
- 갈림길 뒤에는 그 길에서만 생기는 대화가 붙고, 다음 장면의 도입 · 1년 뒤 문구가 지나온 길을 기억한다.
- 엔딩의 「지나온 길」 — 갈림길마다 고른 길 · 고르지 않은 길 · 지나온 장면 · 그 선택이 남긴 한 줄. 홈 카드에는 「경로 n / 4」.
- 경로 장면은 `fork: true` 인 장면이다. 판본(`variants`)에 `chapter · art · view · speaker · day · cost` 를 적으면 그 판본으로 풀릴 때 장면의 것을 덮는다.
- 검증기는 회사마다 네 조합을 끝까지 돌려 모두 '지적 없음'에 닿는지, 만회 넷 · 막힌 길 둘이 실제로 열리는지 본다(`tools/validate.js` 의 `RECOVER`).
- 사진이 없는 인물은 이니셜 초상으로 나온다. 사진을 넣는 법은 `docs/image-prompts.md`.

### 채점 방식 — 기본 채점 / AI 연동 채점
홈 오른쪽 위 「기본 채점」 단추에서 고른다. 기본값은 기본 채점(키워드 엔진)이고, 설치나 로그인 없이 된다.

AI 연동 채점은 **서술 · 판단 칸**의 논점을 Claude 가 판정한다. 객관식 · 빈칸 · 분류 · 미니게임은 그대로다.
판정(논점마다 인정 · 절반 · 불인정, 감점 · 가점 해당 여부, 한 줄 이유)만 받아 오고 점수 셈은 `js/engine.js` 가 그대로 한다 — 부분 점수 상한 · 문장 점수 · 분량 감점 · 분기와 진실 발견의 규칙이 두 방식에서 같다.
제출하면 「AI 채점 중」이 뜨고(시계는 서 있다) 몇 초 뒤 채점표가 나온다. 실패 · 거절 · 시간 초과거나 [기본 채점으로] 를 누르면 기본 채점으로 채점하고 채점표 맨 아래에 그 사실을 적는다.

| 길 | 언제 | 준비 |
|---|---|---|
| 이 PC의 Claude Code | `node tools/serve.mjs` 로 띄웠을 때 | `node tools/serve.mjs --login` 한 번 (브라우저로 로그인). API 키 없음 — 그 계정의 Claude 사용량으로 돈다 |
| API 키 | 배포판 · 다른 사람 | 설정 창에 자기 Anthropic API 키. 키는 그 브라우저(`localStorage`)에만 저장되고 요금은 그 키의 계정으로 청구된다 |

둘 다 되면 이 PC의 Claude Code 를 쓴다. 모델은 설정 창에서 고른다(기본 Sonnet 5.5).
- 로컬 서버의 `/api/grade` 는 같은 출처에서 온 요청만 받는다(다른 웹페이지가 내 사용량을 쓰지 못하게). 도구 없이 한 번 묻고 끝낸다.
- API 키 길은 공식 SDK(`@anthropic-ai/sdk`)를 CDN 에서 모듈로 불러 브라우저에서 직접 부른다. **배포판에 내 키를 넣어 두지 말 것** — 누구나 꺼내 쓸 수 있다.
- `node tools/aigrade-check.js` — Claude 를 부르지 않고, 서술 · 판단 칸 전부에 대해 요청이 만들어지는지와 판정 → 점수 변환이 맞는지 본다.

**채점 지침** — 어느 모델이 채점해도 같은 결과가 나오게 하는 것이 목적이다 (`js/aigrade.js` 의 `SYSTEM`, 고치면 `GUIDE_V` 를 올린다. 채점표에 「AI 채점 · 모델 · 지침 n · 기본 n점」으로 찍힌다).
- 기준은 우리 채점표뿐 — 논점 라벨 · 인정 표현(동의어 사전까지 펼쳐서) · 부분 인정 · 함께 써야 하는 말 · 논점의 뜻 · 모범답안을 그대로 보낸다. 모델의 감사 지식으로 기준을 넓히거나 좁히지 않게 한다.
- 논점 하나씩 정해진 순서로 인정 · 절반 · 불인정만 고르고, 망설여지면 낮은 쪽. 점수는 모델이 세지 않는다. 판정 예를 함께 준다.
- 고정 규칙 — 기본 채점이 정확한 용어로 인정한 논점을 AI 가 불인정하면 절반은 준다. 두 채점의 차이는 채점표에 함께 보인다.
- `node tools/aigrade-calib.mjs [--n 12] [--model … | --all]` — 정답이 정해진 답안(모범답안 · 딴 문항 답안 · 핵심 용어를 뺀 답안)으로 모델이 지침대로 채점하는지, 같은 답안에 판정이 흔들리는지, 모델끼리 같은지를 잰다. 실제로 Claude 를 부르므로 로그인이 필요하고 사용량이 나간다. 기준은 항목마다 90%.

### 단서
장면 데이터의 `clues` 는 지문 · 자료 속 부분 문자열이다. 빨간 점선으로 보이고, 누르면 증거로 채택된다.
채택한 단서는 서술 칸 아래 증거 칩으로 따라다니고, 장면 정산 때 감사증거에 더해진다(최대 +4). 놓친 단서는 정산 뒤 회색으로 드러난다.

```js
    { type: 'mini', game: 'count' | 'jet' | 'cutoff', say, ask, model: '풀이 한 줄' }
  ]
}
```

주의
- 정답은 해설 · 강평 · 기준서로 확인한 것만 넣는다. 기준서 문장은 그대로 옮기지 말고 취지로 쓰되, 빈칸 핵심어는 기준서 용어 그대로
- `judge` 의 판단 문구는 `label` 로 버튼에 보인다. `write` 에 판단을 두면 「판단 문장 필수」 칩이 뜬다
- 오답 보기는 그럴듯하게 — 실무에서 실제로 헷갈리는 선택지(구두 vs 서면, 곧바로 범위제한, 질문만으로 종결, 경영진 동의만으로 종결 등)
- 동의어 사전 묶음을 넓게 잡으면 틀린 답이 정답으로 인정된다 (유형1 · 유형2 보고서를 한 묶음에 두면 안 된다)
- 시점과 화자: 매니저가 묻는 칸은 view 'staff', 파트너 · 어쏘가 묻는 칸은 'senior'
- 대사는 42자 이내 (검증 스크립트가 경고한다)
