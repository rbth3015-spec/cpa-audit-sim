# 감사 시즌 2026

CPA 2차 회계감사 **실전 시뮬레이션 게임**. 설치 없이 브라우저에서 돌아간다.

감사 시즌 하나를 수임부터 감사의견까지 끌고 간다. 회사에는 **무언가가 숨겨져 있고**, 절차를 제대로 밟은 만큼만 드러난다.
놓친 것은 1년 뒤 감리에서 돌아온다. 장면과 장면 사이에는 사람들이 메시지를 보낸다.

감사 대상은 홈에서 고른다.

| 회사 | 장면 | 논점 |
|---|---|---|
| ㈜서린정밀 (코스닥) | 10 | 부정 · 특수관계자 — 수임 검토 → 위험평가 ◆ 재고실사 → 외부조회 ◆ 회계추정치 → 특수관계자 ◆ 기타정보 → 후속사건 ◆ 왜곡표시 평가 → 의견형성 |
| ㈜라온바이오 (코스닥 · 지정) | 8 | 초도감사 · 계속기업 — 감사인 지정 → 기초잔액 ◆ 개발비 자산화 → 기술이전 수익 ◆ 전환상환우선주 → 계속기업 ◆ 후속사건 → 의견형성 |
| ㈜구름결 (코스닥 · SaaS · SI) | 8 | IT 통제 · 데이터 — 감사계획(벤치마크) → IT 일반통제 ◆ 데이터 분석(무결성 · 결합) → 구독 · SI 수익 ◆ 서비스조직 → 특수관계자 ◆ 후속사건 → 의견형성 |

◆ = 돌발 업무 요청 (28건 중 세 장이 뜨고 하나를 고르거나 넘긴다)

세 가지를 목표로 만든다.
1. **학습** — 기출 문체 · 기준서 용어 · 즉시 채점 · 모범답안 대조 · 오답 노트 · 개념 카드
2. **게임** — 단서 찾기 · 판단 버튼 · 미니게임 · 등급 도장 · 연속 보너스 · 숨은 진실 · 36가지 엔딩
3. **쓰기 편한 화면** — 한 화면에 할 일 하나, 같은 정보는 한 번만, 문구는 라벨 · 대사 한 줄

## 실행

```bash
python -m http.server 8765
```
`http://localhost:8765` — `index.html` 을 바로 열어도 된다(데이터를 `.js` 로 두어 `file://` 에서도 돈다).
웹폰트(Archivo · Gowun Batang · IBM Plex Mono · Pretendard)는 인터넷이 없으면 시스템 글꼴로 대체된다.
데스크톱 전용으로 설계했다 (1280px 이상 권장).

디자인 규칙은 인계 디자인(design_handoff_audit_season_2026)을 따른다. 조서 한 장 콘셉트, 모서리 0, 서사는 명조 · 라벨과 수치는 고딕/고정폭, 붉은색은 큰 글자 · 펜 주석 · 제출 버튼, 합계 행 이중선, `tabular-nums`, 다크 모드, `prefers-reduced-motion` 에서 애니메이션 정지.

### 문구 원칙
- UI · 안내는 라벨과 명사형 (「장면 01 / 10」 「편철 완료」 「개념 카드 +2」). 규칙 설명 문단을 두지 않는다
- 도움말은 형식마다 처음 한 번만 한 줄로 뜬다 (TIP)
- 인물 대사는 구어체 한 줄, 문제 문장을 되풀이하지 않는다
- 물음은 기출 문체 (~서술하시오 · ~고르시오 · ~채우시오 · ~분류하시오)
- 개념 카드와 해설은 수험서식 명사형 요약
- 감리 결과 · 조서 문구는 개조식 · 문어체

## 문항 형식

한 장면은 칸 3개이고, 칸마다 형식이 다르다. 형식이 달라도 채점 결과는 같은 모양(must · trap)이라 분기 · 진실 발견 · 개념 카드 로직은 형식을 모른다.

| 형식 | 조작 | 채점 |
|---|---|---|
| `write` 서술 | 답안을 통으로 쓴다. `verdict` 가 있으면 판단 문장까지 써야 한다 | 키워드 엔진(정규화 · 동의어 · 오타 허용 · 부정문 무효 · 근접 조건 · 나열 상한 · 분량 감점) |
| `judge` 판단 | A/B 로 판단을 고르고 근거만 쓴다 | 판단이 틀리면 근거 0점 |
| `choice` 객관식 | 하나 고르기 / 모두 고르기. 보기는 헷갈리게 — 오답마다 왜 틀렸는지 한 줄 | 모두 고르기에서 오답은 감점, 오답 두 개 이상이면 명중 불인정 |
| `cloze` 빈칸 | 기준서 취지 문장의 핵심어 빈칸. 초성 힌트 가능 | 동의어 · 오타(자모 편집거리) 허용, 힌트 쓴 빈칸은 절반 |
| `sort` 분류 | 항목마다 분류를 고른다 (답안 양식 표처럼) | 항목별 채점, 특정 오분류는 감점 · 회사 태도에 연결 가능 |
| `mini` 미니게임 | 재고 실사 · 분개 테스트 · 기간귀속 | 게임별 채점 규칙 (js/minis.js) |

### 미니게임
| 게임 | 쓰이는 곳 | 하는 일 | 배우는 것 |
|---|---|---|---|
| `count` 재고 실사 | 장면 3 | 랙 20칸과 회사 실사표를 양방향으로 대조, 표본 8개를 세고 틱마크(일치 · 수량 차이 · 현품 없음 · 실사표 누락 · 상태 이상) | 실사표→현품 = 실재성, 현품→실사표 = 완전성, 파손 = 평가, 타사 소유 = 제외 |
| `jet` 분개 테스트 | 장면 2 | 전표 24건에 추출 조건 9개를 조합해 위험 분개 5건을 10건 이하로 추출 | 결산 수정분개 · 마감 후 입력 · 경영진 입력 · 드문 계정 조합 · 기말 전후 매출 |
| `cutoff` 기간귀속 | 돌발 업무 c28 | 기말 전후 출고 8건을 타임라인에서 보고 귀속 오류를 표시 | 인도조건별 통제 이전 시점 (선적지 · 도착지 · 검수) |

판은 시즌 코드로 섞인다. 같은 코드면 같은 판이다.

## 시즌 시스템

| 상태 | 뜻 | 화면 |
|---|---|---|
| 감사증거 E | 답안 수준 + 찾은 단서. 45 미만이면 마지막에 범위제한 | 막대 |
| 감사시간 T | 장면 · 업무마다 줄고 0이면 마감 실패 | **보고서 기한 D-day** (T × 0.6일) |
| 신뢰 R | 상급자의 신뢰. 오개념 · 오답 선택에서 급락, 연속 적정 3회마다 +2 | 막대 |
| 회사 태도 | 회사를 세게 밀수록 비협조. 회사 편을 들면(please) 오르지만 신뢰는 떨어진다 | 4칸 · 협조적 / 중립 / 경계 / 적대 |
| 숨은 진실 | 매 시즌 달라지는 왜곡표시 6종. 특정 논점을 정확히 짚어야 발견 | 조서 D 가려진 메모 |
| 시점 | 장면마다 앉는 자리(어쏘 · 시니어 · 업무수행이사)가 바뀐다 | 장면 도입의 팀 세 칸(계급 표시 Ⅰ·Ⅱ·Ⅲ) · 상황 칸의 「나」 칩(자리가 바뀐 장면은 이름이 굴러 바뀐다) |
| 관계 | 사람마다 쌓이는 믿음. 대화 선택과 장면에서 한 일로 움직인다 | 조서 G 인물 · 정산 토스트 |

엔딩은 감리 결과 × 회사의 운명 × 커리어 세 축을 조립하고, 그 뒤에 **사람들의 1년 뒤**와 **독립성 · 윤리 점검**이 붙는다.

### 이야기와 인물
- 인물 19명 — 법인(정한별 · 유가온 · 한결 · 심규리 · 오세진) · 회사 쪽(회사마다 다름) · 외부.
- 장면 사이에 메신저 · 대면 대화가 끼어든다. 답장 선택은 관계 · 게이지 · 분기를 바꾼다.
- 윤리 · 독립성이 걸린 답장은 그 자리에서 판정되고 개념 카드가 된다 (선택지 순서는 시즌마다 섞인다).
- 사진이 없는 인물은 이니셜 초상으로 나온다. 사진을 넣는 법은 `docs/image-prompts.md`.

### 단서
장면 데이터의 `clues` 는 지문 · 자료 속 부분 문자열이다. 빨간 점선으로 보이고, 누르면 증거로 채택된다.
채택한 단서는 서술 칸 아래 증거 칩으로 따라다니고, 장면 정산 때 감사증거에 더해진다(최대 +4). 놓친 단서는 정산 뒤 회색으로 드러난다.

### 감사 대상 추가하기
`data/<회사>.js` 에서 `window.SEASON_<회사> = { COMPANY, SCENES, TRUTH, STORY, CAST, CAST_ORDER }` 로 담고,
`index.html` 에 `<script>` 한 줄, `data/seasons.js` 의 `BOOK` 에 한 줄을 더한다.
회사 쪽 값(중요성 `matNum` · 기본 조정사항 `baseMis` · 돌발 업무 시점 `sideAfter` · 의견 가점 `opinionBonus`)은 COMPANY 에 적는다.

## 문항 추가하기

`data/cases.js` 에 넣으면 업무 요청과 연습 모드에 바로 나온다. 장면(scenes1 · 2)과 형식이 같다.

```js
{
  id: 'c29', tag: '외부조회', chapter: '짧은 제목', area: '감사절차 수행과 결과 보고', src: '출제 출처',

  exhibits: [{ type: 'table', title, head, rows } | { type: 'kv', title, items } | { type: 'memo', title, from, body }],

```

주의
- 정답은 해설 · 강평 · 기준서로 확인한 것만 넣는다. 기준서 문장은 그대로 옮기지 말고 취지로 쓰되, 빈칸 핵심어는 기준서 용어 그대로
- `judge` 의 판단 문구는 `label` 로 버튼에 보인다. `write` 에 판단을 두면 「판단 문장 필수」 칩이 뜬다
- 오답 보기는 그럴듯하게 — 실무에서 실제로 헷갈리는 선택지(구두 vs 서면, 곧바로 범위제한, 질문만으로 종결, 경영진 동의만으로 종결 등)
- 동의어 사전 묶음을 넓게 잡으면 틀린 답이 정답으로 인정된다 (유형1 · 유형2 보고서를 한 묶음에 두면 안 된다)
- 시점과 화자: 매니저가 묻는 칸은 view 'staff', 파트너 · 어쏘가 묻는 칸은 'senior'
- 대사는 42자 이내 (검증 스크립트가 경고한다)

## 출처와 권리

- 상황은 2025년 기출과 GS 의 유형을 이름 · 숫자 · 맥락을 바꿔 새로 썼다. 원문 문항 · 해설은 `자료/` 에만 두고 저장소에 올리지 않는다 (`.gitignore`)
- 빈칸 문장은 회계감사기준의 취지를 풀어 쓴 것이다
- 암기 카드 중 「내 노트」는 사용자의 굿노트 필기를 옮긴 것이라 `자료/deck_notes.js` 에만 두고 저장소에 올리지 않는다
- 상업적으로 배포하려면 기출 · 수험서 · 기준서 인용 범위를 따로 검토해야 한다
